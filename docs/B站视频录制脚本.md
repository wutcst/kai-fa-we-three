## 下半场：代码讲解（约 6-7 分钟）

> 每段：先切回浏览器回放对应画面（5-10秒），再切 IDEA 讲代码

---

### 1. 登录注册（0:00-0:40）

**画面：** 浏览器回放注册+登录画面

**切 IDEA：**
- 打开 `PlayerRepository.java` → 指到 login 方法（第106行）
- 打开 `LoginCommand.java` → 指到 execute
- 打开 `RegisterCommand.java` → 指到 execute

**口稿：**
> "登录和注册在后端是两个独立的命令。PlayerRepository 的 login 方法先查用户是否存在——不存在直接拒绝，存在才验证密码。注册走 RegisterCommand，先检查用户名是否已被占用，再调用 createPlayer 写入数据库。两个功能完全分开，登录不会自动注册。"

---

### 2. NPC 条件对话（0:40-1:15）

**画面：** 浏览器回放保安的两次对话（有地图前/后）

**切 IDEA：** 打开 `TalkCommand.java` → 指到 determineCondition 方法

**口稿：**
> "NPC 对话不是写死的一段话，而是根据游戏状态动态切换的。TalkCommand 的 determineCondition 方法会检查玩家背包、任务进度，返回不同的对话分支。比如保安：第一次对话提醒拿地图，拿到地图后给出任务指引，拿到完美报告后又换一种说法。同一个人，不同阶段说的话完全不同。"

---

### 3. 答题系统（1:15-1:50）

**画面：** 浏览器回放答题过程

**切 IDEA：** 打开 `AnswerCommand.java`

**口稿：**
> "答题系统的核心在 AnswerCommand。它根据当前所在房间判断正确答案——在办公室答案是B，在教学楼答案是A。答对了会解锁被 NPC 锁定的物品、加分加血、奖励金币，同时推进任务进度。每件锁定的物品在 Item 类里有一个 lockedByNpc 字段，答对题后自动解锁并拾取。"

---

### 4. 合成系统（1:50-2:20）

**画面：** 浏览器回放合成过程

**切 IDEA：** 打开 `CraftingManager.java`

**口稿：**
> "合成系统由 CraftingManager 管理。它维护了一个配方表——perfect_report 需要 code_data、reference、signature 三种材料。findCraftable 方法遍历玩家背包，检查是否满足任一配方的材料要求。如果三样齐全就返回可合成的物品名，前端据此显示合成按钮。缺少材料时前端会提示具体缺了哪几样。"

---

### 5. 等级称号（2:20-2:50）

**画面：** 浏览器展示 HUD 的 EXP 条和 Lv 显示

**切 IDEA：** 打开 `Player.java` → getLevelTitle() 方法 打开 `GameConstants.java` → EXP_THRESHOLDS

**口稿：**
> "等级系统从十五级简化到五级，每级都有专属称号。Player 类里 getLevelTitle 方法根据等级返回对应称号——新生、见习探索者、青年研究者、资深学者、学术大师。经验值门槛定义在 GameConstants 里，从六十到五百，经验只能通过完成任务获得。等级不仅影响属性，还会影响结局评分。"

---

### 6. 结局计算（2:50-3:30）

**画面：** PPT 展示 6 种结局

**切 IDEA：** 打开 `EndingCalculator.java` → calculate 方法 打开 `EndingType.java`

**口稿：**
> "结局怎么判定？EndingCalculator 的 calculate 方法按照优先级从高到低匹配：先检查是否同时满足速通、全对、全收集——如果都满足就是全能学者。再检查传送室去了几次——三次以上就是隐藏结局时空旅者。然后依次判断学术之星、闪电学者、校园活地图。最终称号把等级称号和表现称号拼在一起，比如'学术大师 · 时空旅者'。"

---

### 7. 传送室与时间（3:30-4:10）

**画面：** 浏览器回放传送室的时间选择和随机传送

**切 IDEA：** 打开 `TeleportRoom.java` → 打开 `WorldState.java` → 打开 `GoCommand.java` 传送室部分

**口稿：**
> "传送室是整个游戏最有特色的房间。它重写了 getExit 方法——不管往哪个方向走，都随机返回一个房间。结合时间系统，深夜进入传送室可以打开时空传送门，选择想要的时间再传送——比如从深夜跳回早晨找管理员，或者从白天跳到深夜找神谕者。传送室还会记录访问次数，三次以上就是隐藏结局的触发条件。"

---

### 8. 存档持久化（4:10-4:50）

**画面：** 浏览器演示存读档

**切 IDEA：** 打开 `SaveService.java` → save 和 load 方法 打开 `GameSnapshot.java` 打开 SQLite 数据库 → game_save 表

**口稿：**
> "存档系统是持久化的关键。SaveService 的 save 方法先调用 createSnapshot 把当前游戏状态拍成快照——包括当前房间、血量、背包物品、任务进度、游戏时间、传送室访问次数、NPC 好感度等十几个字段。然后通过 SaveRepository 写入数据库。读档时反向操作，从数据库读取快照，通过 applySnapshot 恢复到游戏世界。数据库打开就能看到 game_save 表里每一条存档记录。"

---

### 9. 架构总览（4:50-5:30）

**画面：** PPT 架构图

**口稿：**
> "整个项目的架构是三层：前端 Vue 3 单页应用，所有 UI 在一个 index.html 里完成，包括 Canvas 绘制的游戏场景、SVG 小地图、各种弹窗面板。通过 REST API 调用后端 Spring Boot，GameController 接收请求，GameService 解析命令并执行。后端核心是 Command 模式——每个游戏指令对应一个 Command 子类，通过 CommandWords 注册，目前有二十多个命令。数据库用 SQLite，十张表，包括玩家表、存档表、背包表、任务进度表等。"

---

### 10. 测试与总结（5:30-6:30）

**画面：** IDEA 运行所有测试 → 绿色全部通过

**口稿：**
> "最后是测试。项目共有十二个测试类，覆盖了登录注册、存档读写、答题、合成、结局计算、移动等核心功能。在 IDEA 里右键 test 目录 Run All Tests，全部绿色通过。这个项目从最初的命令行版本，到现在的完整 Web 应用，经历了数据库引入、Web UI 重写、任务系统、等级结局、代码清理多个迭代，最终形成现在六十五个 Java 源文件、十个数据库表、十二个测试类的完整项目。"

## 录制操作步骤

### 准备
1. IDEA 运行 Main.java，确认 localhost:8080 能打开
